# Проблемы, особенности источников и принятые решения

Документ фиксирует трудности, выявленные при анализе источников и разработке системы,
способы их решения и оставшиеся ограничения. Состояние на 27.10.2026.

Итог загрузки:

| Биржа | Проверено дней | Торговых дней | Период | Записей | Без суммы |
|---|---|---|---|---|---|
| ETS | 289 | 289 | 01.07.2025 — 23.10.2026 | 4 278 | 787 (старый формат файлов, см. 1.6) |
| Каспий | 634 | 345 | 04.02.2025 — 27.10.2026 | 6 062 | 0 |

Все дни загружены без ошибок. Повторная загрузка тех же дней не добавляет записей.
У Каспия проверяется каждый календарный день: 289 из 634 — выходные и дни без торгов.

## 1. Источник ETS (ets.kz)

### 1.1 Данные публикуются файлами, а не таблицей на странице
- **Особенность.** Итоги торгов — xlsx-файл на каждый торговый день. Файлы сгруппированы
  по страницам месяцев, месяцы — по страницам годов.
- **Решение.** Парсер работает в два этапа: обход страниц и сбор ссылок на файлы,
  затем скачивание и разбор каждого файла.
- В инструментах разработчика браузера видны запросы `react_section.php`, однако ссылки
  на файлы присутствуют в HTML, который отдаёт сервер. Выполнение JavaScript (Playwright/Selenium)
  не требуется, достаточно `requests` и `BeautifulSoup`.

### 1.2 Адреса страниц не подчиняются единому шаблону
- **Особенность.** Адреса месяцев и годов заданы вручную и различаются по формату:

  | Страница | Адрес |
  |---|---|
  | 2025 год | `/documents/trading-results/2025-god/` |
  | 2026 год | `/documents/trading-results/itogi-torgov-2026/` |
  | январь 2026 | `itogi-torgov-2026-yanvar/` |
  | февраль 2026 | `itogi-torgov-fevral-2026/` (год в конце) |
  | март 2026 | `itogi-torgov-2026-god-mart/` |
  | май 2026 | `itogi-torgov-2026-may/` |

- **Риск.** Формирование адресов по шаблону (год + название месяца из словаря) приводит
  к пропуску месяцев и ошибкам 404.
- **Решение.** Адреса не формируются, а собираются со страниц. Рекурсивный обход:
  на каждой странице берутся ссылки, адрес которых начинается с адреса текущей страницы.
  Это же правило отсекает языковые версии `/kz/`, `/en/`, меню и ссылку на саму страницу.
  Новые месяцы и годы подхватываются автоматически.

### 1.3 Глубина истории
- На сайте доступны только 2025 год (начиная с июля) и 2026 год.
  Самая ранняя загруженная дата — 01.07.2025.

### 1.4 Дата торгов не содержится в таблице
- **Особенность.** В колонках файла даты нет. Она указана в заголовке документа на странице месяца.
- **Проблема.** Атрибут `download` у ссылки на одних страницах содержит дату
  (`04.05.2026 САУДА-САТТЫҚ НӘТИЖЕЛЕРІ_ ИТОГИ ТОРГОВ.xlsx`), а на других — случайное имя
  (`c14xyq800v05zc90m467yzjhxmjwtls6.xlsx`).
- **Решение.** Дата извлекается регулярным выражением из текста заголовка документа
  (`.i_documents_item_title`), одинакового на всех страницах.

### 1.5 Структура xlsx-файла
| Особенность | Решение |
|---|---|
| Строка заголовков находится не на фиксированной строке, первая колонка пустая | строка заголовков ищется по наличию «Наименование товара» |
| Заголовки двуязычные, с переносами строк: `Сатып алушының атауы/\nНаименование покупателя` | колонки сопоставляются по русской части (после последнего `/`) по ключевому фрагменту, а не по номеру |
| Опечатка в источнике: «Средневзвеш**а**нная цена» | поиск по фрагменту `средневзвеш` |
| Строка итога внизу: в разных файлах пустой товар, текст «Итого» в колонке товара или «Общий оборот…» в колонке покупателя | строка считается сделкой только при наличии продавца или покупателя |
| Числа приходят как `float` | преобразование в `Decimal` через строку, хранение в `NUMERIC` |
| Второй лист с технической информацией | читается только первый лист |

### 1.6 Формат файлов менялся
- **Проблема.** При первой полной загрузке 72 дня (01.07.2025 — 16.10.2025) завершились ошибкой
  «В заголовке нет колонок: amount».
- **Причина.** До ~16.10.2025 файл содержал 10 колонок: покупатель, продавец, товар, код товара,
  количество сделок и пять цен. **Отсутствуют** сумма сделки, БИН, брокеры и код ТН ВЭД.
  С ~17.10.2025 — 16 колонок.
- **Решение.** Обязательными колонками оставлены только товар, продавец и покупатель.
  Для старых записей сумма, объём, БИН, брокеры и ТН ВЭД не заполнены (`NULL`).
  Повторный запуск автоматически загрузил ранее упавшие дни.

### 1.7 Смысл строки
- Одна строка файла — не отдельная сделка, а сводка за день по паре
  «покупатель + продавец + товар» (количество сделок, цены открытия, закрытия, минимальная,
  максимальная, средневзвешенная, общая сумма).
- В качестве цены за единицу используется средневзвешенная цена.

### 1.8 Товары
| Особенность | Решение |
|---|---|
| Название в одной ячейке на двух языках: `aq qant, EXW/сахар белый, условия поставки EXW` (казахское — латиницей) | разделение по первому `/` на казахское и русское название |
| Код ТН ВЭД в разных форматах: `2701` (число), `'1001 99 000 0'` (строка с пробелами) | оставляются только цифры |
| Одному названию соответствует несколько кодов товара (разные контракты) | снято ограничение уникальности названия (миграция `9da1b0499c5c`); на ETS товар идентифицируется по коду |
| Условия поставки (базис, станция) входят в название товара | отдельно не выделяются |

### 1.9 Отсутствующие поля (п. 4.1 ТЗ)
| Поле ТЗ | ETS |
|---|---|
| Время торгов | нет |
| Цена с НДС и без НДС отдельно | нет (в названии иногда «цена с НДС») |
| Объём | нет; **вычисляется** как сумма / средневзвешенная цена; для файлов до 10.2025 невычислим |
| Единица измерения | нет; извлекается из названия товара по словарю (т, кг, л, м³, шт), определяется не всегда |
| Место и срок поставки | нет отдельной колонки; входят в название товара |
| БИН, брокеры, ТН ВЭД | есть только в файлах с ~17.10.2025 |

### 1.10 Правила сайта
- `robots.txt` отсутствует: по адресу `/robots.txt` сервер возвращает HTML главной страницы.
  Формальных ограничений нет.
- Тем не менее соблюдается корректная нагрузка (п. 4.2 ТЗ): пауза 1,5 с перед каждым запросом,
  таймауты 10 с (страница) и 30 с (файл), явный `User-Agent`, переиспользование соединения.

## 2. Источник Каспий (ccx.kz)

| Особенность | Следствие |
|---|---|
| Сайт часто недоступен (соединение обрывается по таймауту) | ошибки дня фиксируются в журнале, день повторно загружается следующим запуском; таймаут 20 с |
| Выдача ограничена примерно 1000 строками (67 страниц по 15): запрос без фильтра по дню показывает только последние ~1000 строк, и создаётся ложное впечатление, что история начинается с 03.07.2026. На самом деле данные есть с 04.02.2025 | дни не берутся из общей выдачи, а перебираются по календарю: один запрос на каждый день с `CCX_HISTORY_FROM` (по умолчанию 01.02.2025) по сегодня |
| Данные в HTML-таблице `table.custom-table-flexible`, 15 строк на страницу, пагинация `?page=N` | при появлении новых записей содержимое страниц сдвигается; сделки загружаются по одному дню (`date_from` = `date_to`) |
| Количество страниц в HTML не указано (ссылок с номерами страниц нет) | страницы перебираются по порядку |
| Номер страницы за пределами конца (`page=68`, `page=200` при 67 страницах) возвращает **последнюю страницу ещё раз**, а не пустую | перебор останавливается, когда страница повторяет предыдущую; защитный предел — 500 страниц |
| В день без торгов (выходной) таблицы нет, вместо неё — `<div class="empty-state">Нет данных для отображения</div>` | только это сообщение считается подтверждением пустого дня; такой день сохраняется как загруженный с 0 записей. Страница без таблицы и без сообщения — ошибка |
| Порядок строк в таблице не постоянен между запросами | строки никогда не выбираются по номеру; итог дня отсекается по смыслу, дубли строк между страницами — по содержимому |
| Первая строка дня — итог («ИТОГО по дате»: общий оборот за день, количество сделок), участники не указаны | пропускается по правилу «нет участника — не сделка»; оборот за день не хранится, он вычисляется суммой |
| Названия товаров — полное техническое описание, до 400+ символов | длина названия товара в базе увеличена до 1000 символов (миграция `96878e9ed551`) |
| В названиях встречаются единицы в составе характеристик («5000 ккал/кг») | единица после `/` не считается единицей товара (иначе уголь определялся бы как «кг») |
| Пустые значения в ячейках — символ `-` | приводится к `NULL` |
| Без параметра `lang` страница отдаётся на казахском языке | загружается русская версия (`lang=ru`); казахские названия товаров Каспия не загружаются (см. раздел 7) |
| БИН не вынесен в отдельную колонку, а дописан в конец наименования участника: `АО Майкубен-Вест 050940003769`; указан не у всех | БИН отделяется от наименования (12 цифр в конце строки); участники без БИН сопоставляются по названию (см. 3.2) |
| Длинные значения в ячейке обрезаются многоточием прямо в HTML: `…Цементный завод Семей 02124000002…` — обрезанным оказывается и БИН. Полное значение лежит в атрибуте `title` у `<span class="td-text">` | значение ячейки берётся из `title`, если он есть, иначе видимый текст. Обнаружено при проверке поиска: 7 участников в 78 днях были записаны с обрезанным названием и без БИН; Каспий перезагружен целиком |
| Числа с пробелом-разделителем тысяч и точкой: `103 681 783.54` | общая функция `to_decimal` |
| Есть «Условие поставки» (EXW, FCA, DDP…) | единственный источник поля «условия поставки» |
| Нет кода товара (есть только у ETS) | товары Каспия сопоставляются по нормализованному названию |
| Нет времени сделки, цены отдельно с НДС и без НДС, единицы измерения, объёма | объём вычисляется как сумма / средневзвешенная цена; единица — из названия товара |

Первая загрузка Каспия — около 630 запросов (каждый календарный день, включая выходные), ~20 минут.
Ежедневный запуск — около 4 запросов: новый день и перепроверка последних дней (см. раздел 4).

## 3. Проектирование базы данных

### 3.1 Защита от дублей
- **Проблема.** Уникальный индекс по набору колонок (дата, товар, продавец, покупатель, брокеры)
  не защищает от дублей: в PostgreSQL `NULL ≠ NULL`, и строки без брокера или БИН
  вставляются повторно.
- **Решение.** Колонка `dedup_hash` — SHA-256 от нормализованных значений строки, с уникальным индексом.
  Вставка: `INSERT … ON CONFLICT (dedup_hash) DO NOTHING`.
- **Особый случай.** В одном файле встречаются полностью одинаковые строки.
  В хеш добавляется порядковый номер повтора внутри файла, чтобы не потерять такие строки
  и при этом не дублировать их при повторной загрузке.
- **Проверка.** Повторная загрузка тех же дней: добавлено 0, пропущено как дубли — 68 из 68.
- **Исправления на бирже.** Биржа может исправить сумму уже опубликованной сделки или удалить
  ошибочную. Если бы день дописывался к старым данным, исправленная сделка появилась бы второй
  записью, а удалённая осталась бы навсегда.
  **Решение:** день **заменяется целиком** в одной транзакции — удаляются все записи биржи за этот день
  и вставляются свежие. При ошибке откатывается и удаление. Проверено: испорченная в базе сумма
  восстановилась, лишняя запись удалена («биржа убрала 1 записей»).
- **Защита от ошибочного стирания.** День заменяется только при явном подтверждении содержимого:
  пришла хотя бы одна сделка, либо (Каспий) страница содержит сообщение «Нет данных для отображения».
  Ошибка сайта, страница без таблицы и без этого сообщения, xlsx ETS без сделок — ошибка дня в журнале,
  данные в базе не трогаются.
- Отпечаток `dedup_hash` остаётся: он отсекает одинаковые строки внутри одной загрузки.
  В журнале «добавлено» — строки, которых раньше не было, «дублей» — совпавшие с уже загруженными.

### 3.2 Сопоставление справочников
| Справочник | Правило | Ограничение |
|---|---|---|
| Товары | ETS — по коду товара; Каспий — по нормализованному названию | названия одного товара на разных биржах могут не совпасть |
| Участники | при наличии БИН — по БИН, иначе по нормализованному названию | БИН указан не у всех (на ETS — с ~17.10.2025, на Каспии — не у каждого участника): участник без БИН может не совпасть с тем же участником, у которого БИН есть; разные организации с одинаковым названием без БИН объединятся |
| Брокеры | по нормализованному названию | — |

Нормализация названия: нижний регистр, `ё → е`, удаление кавычек всех видов, схлопывание пробелов.
Нечёткое объединение («похожие названия») сознательно не применяется: «пшеница 3 класса» и
«пшеница 4 класса» почти совпадают, а ошибочно объединённые записи нельзя разделить обратно.

### 3.3 Деньги
- Суммы и цены хранятся в `NUMERIC(18,2)`, объём — в `NUMERIC(18,3)`, в коде — `Decimal`.
  `float` не используется из-за погрешности двоичного представления.

### 3.4 Изменение схемы
- `db.create_all()` создаёт только отсутствующие таблицы и не изменяет существующие.
- **Решение.** Миграции Flask-Migrate (Alembic): каждое изменение схемы — файл в репозитории.
- Автогенерация воспринимает переименование колонки как удаление и создание (потеря данных),
  поэтому сгенерированные файлы проверяются вручную.

## 4. Надёжность загрузки

| Требование ТЗ 4.2 | Реализация |
|---|---|
| Недоступность сайта не приводит к потере данных | каждый торговый день сохраняется в отдельной транзакции; ошибка откатывает только этот день |
| Изменение структуры страницы | парсер проверяет наличие ожидаемых элементов и колонок и выбрасывает ошибку с описанием, а не возвращает пустой результат |
| Ошибки записываются в журнал | таблица `parser_runs` (время, статус, добавлено, дубли, текст ошибок); запись создаётся в начале запуска |
| Повторный запуск без дублей | день заменяется целиком в одной транзакции; `dedup_hash` + таблица `trading_days` (какие дни загружены) |
| Догрузка пропущенного | загружаются дни, которые есть на сайте и отсутствуют в `trading_days` со статусом `loaded`; дни с ошибкой повторяются автоматически |
| Итоги за последние дни могут появиться на бирже с опозданием | последние `RECHECK_DAYS` дней (по умолчанию 3) перепроверяются при каждом запуске, даже если уже загружены; дубли отсекаются `dedup_hash` |

Проверено на практике: 72 дня старого формата при первой загрузке завершились ошибкой,
217 дней загрузились; после исправления парсера повторный запуск загрузил только 72 недостающих дня.
Второй случай — сбой самого сайта: при полной перезагрузке Каспия сайт начал обрывать соединения
(`ConnectionError: Connection aborted`), 255 дней из 634 завершились ошибкой. Данные этих дней
в базе не пострадали — день заменяется только после успешной загрузки. Следующий обычный запуск
взял только дни со статусом «ошибка».

## 5. Инфраструктура и окружение

| Проблема | Проявление | Решение |
|---|---|---|
| Гонка при создании таблиц | 4 воркера gunicorn одновременно выполняли `create_all`, контейнер падал с `UniqueViolation` | миграции и заполнение справочников выполняются один раз до запуска воркеров: `flask db upgrade && flask seed && gunicorn …` |
| Конфликт порта 5432 | на машине установлен PostgreSQL (служба для 1С); подключение к `localhost:5432` попадало в него, миграции применялись не в ту базу без ошибок | проброс порта контейнера изменён на `5433:5432`; таблицы из чужого сервера удалены через `flask db downgrade base` |
| Порт внутри Docker | при массовой замене `5432 → 5433` изменился и адрес `db:5432` для контейнера бэкенда | внутри сети Docker используется порт контейнера (`db:5432`), проброс влияет только на подключения с хоста |
| Размер образа | в контекст сборки попадал локальный venv (72 МБ) | добавлен `backend/.dockerignore`; контекст сборки — около 2 КБ |
| Синтаксис `.dockerignore` | `__pycache__` исключал только папку в корне | шаблон `**/__pycache__` |
| Перезапуск без пересборки | `docker compose restart` запускает старый образ со старым кодом | после изменения кода — `docker compose up -d --build` |
| Файлы миграций | `flask db migrate`, запущенный в контейнере, создаёт файл внутри контейнера | `migrate` выполняется локально, в контейнере — только `upgrade` |
| Предупреждение gunicorn | `Control server error: Permission denied: '/nonexistent'` | у системного пользователя контейнера не было домашней папки; создаётся с `--home` |
| Медленная сборка образа | `chown -R` после копирования кода обходил все файлы | `COPY --chown` выставляет владельца при копировании |
| Нехватка памяти на машине разработки | одновременно работали Docker (WSL), сервер 1С, SQL Server, VS Code, браузер | Docker останавливается, когда не нужен (`docker compose stop`); службы 1С и SQL Server не нужны проекту |
| Образ базы без версии (`postgres`) на другой машине скачал бы последнюю версию PostgreSQL, отличную от проверенной | версия зафиксирована: `postgres:18` |
| Опасение, что бэкенд в Docker подключится к PostgreSQL от 1С | бэкенд обращается к базе по имени сервиса `db` во внутренней сети Docker (проверено: подключение идёт к IP контейнера `db`); Postgres на компьютере так недоступен. Занятый порт на другой машине даёт явную ошибку `port is already allocated`, а не подключение к чужой базе |
| Кодировка консоли Windows | кириллица в выводе Python отображается некорректно | только отображение, данные корректны; `PYTHONIOENCODING=utf-8` |

## 6. Серверная часть и интерфейс

| Проблема | Решение |
|---|---|
| `rowcount` многострочного `INSERT` возвращает `-1` — счётчик добавленных записей неверный | подсчёт вставленных строк через `RETURNING id` |
| При сортировке по убыванию PostgreSQL выводит пустые значения первыми | `NULLS LAST` |
| Параметр сортировки из запроса нельзя подставлять в SQL | белый список допустимых колонок |
| Таблица на 50 строк порождала бы сотни запросов к справочникам (N+1) | `joinedload` — справочники загружаются вместе со сделками |
| Портал не должен обращаться к биржам (п. 3 ТЗ) | API читает только локальную базу |
| Next.js App Router требует `page.tsx` в каждой папке маршрута, папка `pages/` конфликтует с ним | фронтенд переведён на Vite + React Router: маршруты в одном файле, страницы в `pages/<Страница>/` |
| Redis | не используется: нагрузка минимальна, расписание реализуется APScheduler (п. 4.3 ТЗ) |
| Фильтр «продавец или покупатель» должен искать по двум колонкам и по названию или БИН | подзапрос `id IN (...)` по справочнику участников для обеих колонок; 12 цифр — точный поиск по БИН |
| Таблица и сводка под ней должны считаться по одной выборке | один список условий фильтра используется и для страницы, и для сводки |
| Спецсимволы в поиске (`%`, `_`) работали бы как шаблоны SQL `LIKE` | поиск с экранированием (`autoescape`) |
| Некорректные значения фильтров (дата «мусор», сумма-текст) | игнорируются, а не приводят к ошибке |
| «Место поставки» у ETS не выделено в колонку | фильтр ищет и в условии поставки (Каспий), и в названии товара (ETS) |
| Запросы на каждую букву при вводе в фильтры | значения применяются по кнопке «Применить»; без перезагрузки страницы |
| Расписание нельзя запускать внутри gunicorn: 4 воркера запустили бы 4 одновременных загрузки | отдельный сервис `scheduler` из того же образа; `max_instances=1` |
| Парсинг за период из портала длится минуты, а gunicorn обрывает запрос через 30 секунд | `POST /api/parse` запускает загрузку в фоновом потоке и сразу отвечает «запущено»; ход — в журнале, страница опрашивает статус каждые 5 секунд, пока идёт загрузка |
| Повторный запуск, пока идёт загрузка той же биржи | ответ 409 «Уже идёт загрузка…», кнопка заблокирована |
| Дата «сегодня» в окне запуска ночью получалась вчерашней: `toISOString()` возвращает дату по UTC, а Алматы — UTC+5 | дата берётся из локальных компонентов (`getFullYear/getMonth/getDate`) |
| Средняя цена за месяц как среднее арифметическое цен давала бы мелким сделкам тот же вес, что крупным | цена за месяц = сумма / объём (средневзвешенная) |
| Названия товаров Каспия по 400+ символов не помещаются в подписи графика | топы товаров и участников — таблицами с полосой-шкалой, графики — для оборота и цен |
| Экспорт должен совпадать с таблицей | общая функция построения запроса (фильтры + сортировка) для таблицы и для выгрузки |
| Компьютер выключен в момент запуска по расписанию | пропущенный запуск не выполняется задним числом, но следующий запуск загрузит все пропущенные дни (сравнение с `trading_days`) |

## 7. Ограничения

- Для записей ETS до ~16.10.2025 отсутствуют сумма, объём, БИН, брокеры и ТН ВЭД — ограничение источника.
- История доступна: ETS — с 01.07.2025, Каспий — с 04.02.2025.
- Единица измерения определяется эвристически по названию товара и заполнена не для всех товаров.
- Участники без БИН сопоставляются по названию (см. 3.2); одна организация может встречаться
  дважды (с БИН и без), разные организации с одинаковым названием без БИН объединяются.
- Один и тот же товар на ETS и Каспии — разные записи справочника (названия и коды не совпадают).
- Казахские названия товаров загружаются только для ETS.
- Поиск по подстроке (`LIKE '%…%'`) не использует обычные индексы; при росте базы до сотен тысяч
  записей понадобится индекс `pg_trgm`.
- Ручной запуск из портала работает в фоновом потоке процесса бэкенда. Если контейнер перезапустить
  во время загрузки, запуск останется в журнале со статусом «выполняется»; блокировка повторного
  запуска снимается через 3 часа, загруженные дни при этом не теряются.
- Два очень быстрых нажатия «Запустить» подряд могут запустить две загрузки одной биржи;
  данные не задвоятся (день заменяется целиком), но работа выполнится дважды.
- Экспорт в Excel ограничен 100 000 строк за раз.
- Из дополнительных заданий п. 11 ТЗ выполнены экспорт в Excel, графики и сводная аналитика,
  запуск через Docker; ленты новостей и автотестов нет.
